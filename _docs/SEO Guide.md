# Audiment Website Correction Plan (Founder-Grade Revision)

## Purpose

This document defines:

* what is currently wrong with the Audiment website,
* why it is strategically problematic,
* and what direction the implementation should move toward.

This is NOT an SEO-only correction plan.

This is a:

* positioning correction,
* operational realism correction,
* conversion-quality correction,
* UX correction,
* and semantic refinement plan.

The goal is:
to make the website feel like a believable, high-trust operational SaaS company – not an SEO-generated audit product.

---

# CORE POSITIONING (NON-NEGOTIABLE)

Audiment is:

> Proof-based audit and inspection software for multi-location businesses.

Important:

* Proof is the mechanism.
* Operational visibility and accountability are the outcome.

The website must NOT drift into:

* surveillance software,
* anti-fraud software,
* generic workflow software,
* vague enterprise compliance software,
* or SEO-generated operational jargon.

The tone should feel:

* operational,
* grounded,
* specific,
* believable,
* execution-oriented,
* and manager-friendly.

NOT:

* futuristic,
* hyper-aggressive,
* fear-marketing-heavy,
* or over-engineered.

---

# CURRENT MAJOR PROBLEMS

# 1. Overuse of "ground truth"

Problem:
The phrase "ground truth" is used excessively across:

* homepage,
* about page,
* solutions,
* blogs,
* comparison pages.

This creates:

* repetitive language,
* category-invented feeling,
* weaker readability,
* and AI-generated tone.

Required correction:

* Reduce usage dramatically.
* Use selectively.
* Replace with natural operational language:

  * trustworthy operational visibility
  * verified operational data
  * evidence-backed audits
  * branch-level visibility
  * operational clarity
  * verified inspections

Important:
The website should NOT revolve around one slogan repeated everywhere.

---

# 2. Website sounds too anti-fake-audit focused

Problem:
The website currently over-emphasizes:

* fake audits
* pencil-whipping
* eradication
* un-falsifiable systems
* blind faith
* catastrophic incidents

This creates:

* surveillance-product energy,
* paranoia-heavy positioning,
* and fear-based messaging.

Required correction:
Rebalance the site toward:

* operational consistency
* leadership visibility
* accountability
* execution quality
* cross-location oversight
* issue resolution
* operational confidence

Important:
The website should feel:

* operationally empowering,
  NOT:
* fear-driven.

---

# 3. Homepage positioning regression

Current title:

> Audiment | Ground truth for multi-location audits

Problem:
This weakens:

* category clarity,
* discoverability,
* SEO alignment,
* and product understanding.

Required correction:
Homepage title must clearly communicate:

* audit software
* inspection software
* multi-location operators
* proof-based positioning

Preferred direction:

> Proof-Based Audit Software for Multi-Location Businesses | Audiment

or similar.

---

# 4. H1s are SEO-shaped instead of human-shaped

Examples:

* Restaurant Audit Software – Ensure Hygiene, Safety and Brand Standards Across Every Location
* Corrective Action Tracking Software – Close the Loop on Every Audit Failure

Problem:
These feel:

* templated,
* keyword-first,
* visually heavy,
* emotionally flat,
* and SEO-generated.

Required correction:
Headlines should:

* sound natural,
* feel memorable,
* reinforce positioning,
* and preserve readability.

Keywords should still exist,
but NOT dominate the heading structure.

Preferred direction:
Instead of:

> Restaurant Audit Software – Ensure Hygiene...

Move toward:

> Restaurant Audits You Can Actually Trust

Then use:

* subheadings
* supporting copy
* metadata
* and body content

to handle keyword depth.

---

# 5. Landing pages are too thin

Current structure:

* hero
* pain points
* features
* FAQs
* CTA

Problem:
Pages currently lack:

* operational depth,
* workflow detail,
* educational value,
* implementation clarity,
* decision-support content,
* real-world examples,
* and managerial reality.

This weakens:

* SEO depth
* AI retrieval quality
* conversion quality
* buyer trust
* topical authority

Required correction:
Major pages must become:

* operationally rich,
* educational,
* and conversion-capable.

Every important page should include:

* operational realities
* workflow explanations
* real audit examples
* implementation logic
* leadership outcomes
* operational bottlenecks
* issue-resolution flows
* role-based visibility
* FAQs
* decision-support content

The pages should feel:

* like operational systems,
  NOT:
* SEO landing pages.

---

# 6. Product-truth drift

Problem:
Some pages imply product categories/features that distort the actual product.

Biggest example:

* Field Audit App

Problem:
Audiment is NOT a standalone field-audit app company.

This creates:

* category confusion,
* misleading expectations,
* and SEO-driven product distortion.

Required correction:

* Delete the Field Audit App page entirely.
  OR
* merge useful concepts into broader operational pages.

Important:
Do NOT create fake SEO categories.

The website must ONLY reinforce:
what the product ACTUALLY is.

---

# 7. Navigation architecture is weak

Current issue:
"Solutions" directly opens Restaurant Audit Software.

Problem:
This accidentally positions restaurants as:

* the primary company identity.

Required correction:
Implement either:

* a proper Solutions dropdown,
  OR
* a /solutions overview hub page.

Required structure:

* Restaurants
* QSR
* Food Safety
* Retail
* Franchise
* Hotels
* Manufacturing

Navigation must feel:

* intentional,
* scalable,
* and category-aware.

---

# 8. CTA system mismatch

Current issue:
Navbar includes:

* "Go to app"

Problem:
This creates:

* self-serve SaaS expectations,
* PLG-style UX patterns,
* and onboarding confusion.

Actual sales motion is:

* consultative,
* demo-led,
* operational onboarding,
* sales-assisted.

Required correction:
Primary CTA system should revolve around:

* Book a Demo
* Book a Call
* Request Pricing
* See Audiment in Action

NOT:

* Start free
* Free trial
* Go to app
* Instant signup

The website must match the actual buying motion.

---

# 9. Blog tone is stronger than landing page tone

Observation:
Blog content currently feels:

* more operational,
* more believable,
* more grounded,
* and more insightful

than many commercial landing pages.

Required correction:
Landing pages should adopt:

* the same operational realism,
* practical language,
* and grounded insight quality

already visible in the blog content.

---

# IMPLEMENTATION PHILOSOPHY

Do NOT:

* rewrite everything mechanically,
* over-optimize keywords,
* create keyword-stuffed sections,
* invent fake product categories,
* create fear-heavy messaging,
* or overuse positioning slogans.

Instead:

* strengthen operational realism,
* deepen workflow clarity,
* improve educational richness,
* reinforce leadership outcomes,
* and preserve believable product truth.

The final website should feel:

* operationally credible,
* strategically differentiated,
* conversion-ready,
* and semantically authoritative.

NOT:

* SEO-generated,
* template-heavy,
* or artificially optimized.
